# ScaleRiff 개선·추가사항 관리

이 문서는 개선 논의, 구현 상태, 검증 근거와 남은 한계의 지속적인 기록이다.
새로운 문제가 나오면 항목을 먼저 추가하고 구현 및 검증 후 상태를 갱신한다.

## 승인 범위 — 2026-10-20

사용자가 개선안 1~6을 권장 순서로 실행하고 **점수제까지 통합 완성**하도록 승인했다.
기존의 채점 제거 방침보다 이 승인이 우선한다. 기존 사용자 수정과 화면 흐름은 보존한다.

## 목표와 원칙

- 대상: 곡을 연주할 수 있지만 즉흥에 익숙하지 않은 중급자, Windows + MIDI 피아노.
- 분석·생성은 준비/사용자 액션 시 계산하고 재생 중에는 계산된 Timeline을 사용한다.
- 곡 분석 결과는 추정이다. 자동 분석의 한계를 표시하고 사용자 수정이 우선한다.
- 즉흥의 점수는 주어진 연습 목표에 대한 참고 지표다. 음악적 가치나 창의성 점수가 아니다.
- 리프 모방은 음높이·시작 시각·누락·추가음을 비교한다. 자유 즉흥은 강박 착지와 목표 수행을 설명하며 경과음을 일괄 오답 처리하지 않는다.
- 모델의 성능 비교와 실제 사람의 학습 효과를 별도로 기록한다.

- [음악 분석 평가](MUSIC_EVALUATION.md): 동일100 BPM C–Am–F–G 합성음의 지속 코드/타악 두 조건을 실제 분석했다. 타악 조건 추정99.4 BPM, 코드 정확도 원시76.9%/세션77.0%, 비트F1=0.985, 다운비트F1=0.000. 지속 코드는 비트0개로 기본100 BPM 격자를 사용했으며 검출 성공으로 계산하지 않았다. 두 조건의 빌드·리프·저장·복원 통과, 리프 경계 위반0건.
- [AI 평가](AI_EVALUATION.md): 규칙/부트스트랩/기존 학습 모델 각각40프레이즈의 지원 착지·스케일 게이트100%, 경계 위반0건. 원본 WJazzD에서4/4 프레이즈14,492개를 새로 준비하고 학습229곡/검증57곡, 겹침0곡으로 분리했다.
- 재학습 전체 토큰 log loss=1.722로 균등2.639보다 낮지만 온셋만은3.210으로 균등2.639보다 높았다. 새 모델을 실제 모델에 자동 승격하지 않았으며 생성 자연스러움의 개선으로 해석하지 않는다.
- 두 평가 CLI의 MD/JSON과 평가용 WAV/세션은 같은 환경에서 각각 두 번 실행해 동일 결과를 확인했다. 원본 data/phrases.jsonl과 models/*.json은 변경하지 않았다.

## 구현 중 결정

- 수동 코드 수정은 Segment 객체를 교체할 수 있다. 화면/테스트는 저장해 둔 이전 객체가 아닌 Timeline에서 시간으로 현재 구간을 조회한다.
- 연주 기록과 결과는 Timeline.practice_history에 함께 저장해 별도 전역 JSONL과의 불일치를 피한다.
- 세션 저장은 원자 replace를 사용하고, 원본 오디오가 이동하면 상대 참조 또는 사용자 파일 선택으로 연결한다.
- 모든 스크립트를 `tools/run_checks.py`로 실행한다. `tests_mir_real.py`는 외부 다운로드가 필요하므로 기본 오프라인 검사와 구분한다.
- 실행/학습 설명을 Python3.12/.venv로 맞추고 검증된 버전은 requirements-tested.txt 제약으로 남긴다. 선택적 madmom은 이번 환경에서 검증하지 않았다.
- 실제 입력 장치가 없어도 Qt와 분리한 MIDI 수신·연주 기록·채점은 자동 검사한다. 이를 실기기 검증으로 표기하지 않는다.
- 현재 관리형 `.venv`에는 pip 모듈이 없어 pip check는 실행하지 못했다. 설치 메타데이터로 런타임 의존성과 extras의 버전 조건을 별도 검사해40개 패키지에서 충돌0건을 확인했다. 새 환경의 전체 설치 재현과 현재 환경 실행 검증을 구분한다.
