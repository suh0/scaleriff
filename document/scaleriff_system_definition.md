# ScaleRiff 시스템 정의서 — 2026-10-21 구현 기준

이 문서는 실제 동작의 기준이다. 개선·추가 논의와 미검증 항목은 `IMPROVEMENTS.md`에서 관리한다.
기존 주석의 § 번호를 유지한다. 2026-10-20 사용자 승인으로 점수제와 연습 흐름을 다시 통합했다.

## 0. 한 줄 요약

학습된 통계 모델과 곡 분석을 이용해 피아노의 모방·변주·즉흥 연습, 목표별 피드백, 자기 연주 재청취를 지원한다.

## 1. 목표와 타겟

곡을 연주할 수 있지만 즉흥에 익숙하지 않은 중급자를 대상으로 한다. 초기 범위는 Windows와 MIDI 피아노/화면 건반이다.
오른손 단선율 리프와 저음/고음 목표를 안내한다. 즉흥의 음악적 가치와 창의성을 수치화한다고 주장하지 않는다.

## 2. 전체 흐름

### 2.1 화면

링크/파일/세션 → 분석 → 박자 조정 → 코드 편집 → 코드·스케일/기본 예시 → 연습.
링크 화면의 최근 저장경로 표시와 단계별 박자/코드 편집을 유지한다. 분석은 별도 프로세스에서 실행하며 취소 시 자식 프로세스와 임시파일을 정리한다.

### 2.2 파이프라인

`ingest.audio_source` → `ingest.mir_extract` → `analyze.structure` → `analyze.harmony/theory`
→ `build.real_builder` → `player.timeline.Timeline` → `ml.generate` → `gui.main_screen`.

## 3. 분석과 음악이론

### 3.1 MIR

librosa 기반 비트/키/코드 추정, 선택적 madmom 모델 경로를 지원한다. 자동 코드 어휘는 장·단 3화음이다.
비트가 충분하지 않으면 균등 기본 격자를 만들되 `beat_detected=False`를 저장하고 박자 화면에서 알린다.
키·코드·다운비트는 추정값이며 사용자가 확인/보정한다. 화성 시작보다 늦은 다운비트에 맞춰 실제 곡 시작을 버리지 않는다.

### 3.2 구조

마디별 대표 코드는 반복 패턴 탐지에 사용한다. 연주용 Segment는 원래 코드 시각을 유지해 마디 안의 코드 변화도 보존한다.
첫 다운비트 전 실제 음악은 불완전 시작 마디로 보존한다. 자동 다운비트 위상/박자 정확도는 평가 문서에서 별도로 기록한다.

### 3.3 화성

키·다이아토닉 관계와 코드 품질로 교육용 기본 스케일 하나를 추천한다.
7개 다이아토닉 모드 외 dim7은 whole-half 디미니시드, aug는 온음 스케일을 사용해 이름/음집합/가이드/생성을 맞춘다.
추천은 현재 과제를 위한 기본값이다. 고급 altered 화성과 모든 음악적 대체 스케일은 지원 범위 밖이다.

## 3.5 사용자 보정

박자 조정에서 BPM/박자/시작점을 바꾸고 확인하면 코드 편집으로 이동한다.
시작점만 옮길 때는 가변 마디 간격을 보존하고, BPM/박자 직접 보정은 균등 격자를 사용한다.
원본 `chord_spans`와 `chord_overrides=[시작초,끝초,코드]`를 분리해 재격자화 후 수동 수정을 재적용한다.
루프도 원본 시작/끝초를 보존하고 화면의 마디 번호를 다시 매핑한다.
한 코드가 여러 마디에 걸쳐도 선택한 마디의 시간 범위만 수정한다. 마디 안에 여러 코드가 있으면 먼저 구간을 고른다.
키 변경은 기존 시간/코드 구간을 유지하고 가이드와 리프를 다시 계산한다.
음수 프리롤 마디에는 코드와 리프를 만들지 않는다. 프리롤 후 코드 편집에도 이 조건을 유지한다.

## 4. 아키텍처 불변식

- Timeline이 곡/수정/연주 기록의 저장 상태다. 화면은 이를 조회하거나 명시적인 편집을 수행한다.
- 분석, 프레이즈 생성, 속도 변환은 준비/사용자 액션에 수행한다. 재생 틱은 위치·가이드·예약음 처리만 수행한다.
- 모든 시각은 원본 오디오 초다. `beat_at/time_at_beat/beats_between`이 비트와 원본 초를 변환한다.
- 속도 변경은 연습용 오디오 캐시를 사용하고 device seconds를 원본 초로 환산한다.

## 5. 세션 스키마

JSON `schema_version=2`. 필수 곡 정보와 Segment 외에 다음을 저장한다.

- 분석: audio_ref, wav_ref, bpm/time_sig/key, content_span, bar_times, beat_times, chord_spans, analysis_info.
- 사용자 수정: chord_overrides, key_override, timing_override, loops, split_point.
- 생성: available_scales, scale_riffs, seg.example, model_info(출처/학습 수/파일/해시).
- 연주: practice_history의 시작/끝초, 음높이/시각/길이/물리 키 길이/강약/채널, 과제·점수·모델 정보.

구 형식은 기본값으로 로드한다. 미래 버전, 잘못된 JSON 루트와 비증가 격자를 거부한다.
같은 폴더 임시파일→flush/fsync→원자 replace로 저장한다. 미디어 상대 참조도 기록하며 누락 시 재연결한다.
저장 실패는 사용자에게 표시한다. 미완료 시킹/모드 변경 전 기록은 현재 채점에서 제외한다.

## 6. 화면과 조작

기존 검정/흰색 디자인, 파랑 근음·초록 코드톤·회색 스케일 안내와 다음 구간 예고를 유지한다.
연습 화면 상단에서 단계·구간·착지 목표를 선택하고 하단의 재생/도전/루프를 사용한다.
과제 결과는 점수·대응 수·누락/추가·다음 제안과 표본 수를 표시한다.
입력·소리 설정에 장치 연결/재연결, 음정 유지 속도, 3종 음량, 지연 보정, 음역 경계를 모은다.

## 7. 연습 모드

기존 자유연습/리프연습/스케일도전 Lv1~3/리프도전을 유지한다. 도전 중에는 시킹·루프·모드 변경을 잠근다.

학습 단계는 같은 선택 구간에서 다음 순서로 진행한다.

1. 듣기: 실제 진행 조건의 리프를 듣는다. 입력을 채점하지 않는다.
2. 따라 치기: 낙하 가이드를 보며 연주한다. 예시 소리는 쉬며 MIDI 입력만 기록한다.
3. 변주: 예시 변주를 준비하고, 리듬/끝음을 바꿔 직접 연주한다. 건반 가이드를 숨긴다.
4. 자유 즉흥: 같은 진행과 착지 목표로 연주한다. 경과음 전체를 감점하지 않는다.
5. 다시 듣기: 선택 구간과 겹치는 최근 자기 기록을 원곡과 함께 재생한다. 다시 채점/기록하지 않는다.

다음 듣기로 돌아갈 때 재청취한 기록의 점수에 따른 목표/밀도 제안을 적용한다.
자동 추천은 규칙 기반이다. 모델 가중치는 오프라인 학습으로 갱신한다.

## 7.5 연주 기록과 점수

`player.performance.PerformanceRecorder`와 `player.scoring`은 Qt와 독립적이다.
입력 note-on/off·강약·채널·페달을 원본 시각으로 기록하며 반복 타건/페달 지속을 처리한다.
재생 종료·일시정지/루프 경계에서 유효한 기록을 정리한다. 시킹은 이전 기록을 무효화하고 재생 중이면 새 위치에서 기록을 시작한다.
화면 이동·모드/과제 변경은 미완료 기록을 취소한다. 무연주는 0점 대신 이유를 표시한다.

- 모방: 같은 MIDI 음과 ±0.25박 이내 후보에 대해 최대 대응 수/최소 시간차로1:1 매칭한다.
  F1=2×일치/(기준음+연주음). 총점=100×F1×(0.7+0.2×타이밍+0.1×음길이).
  타이밍은 허용 오차 대비 비율, 길이는 실제/기준 길이 중 짧은 값/긴 값이다.
- 스케일: Lv1 저음 근음/고음 코드톤, Lv2 저음 근음/고음 스케일, Lv3 저음 코드톤/고음 스케일.
  목표음 비율60%+지원되는 착지 목표40%. 없는 3도/7도는 요구하지 않으며 착지 목표가 전혀 없으면 목표음만 평가한다.
- 변주/자유: 고음 영역에서 코드 전환/마디 첫박의 지정 착지 달성률. 스케일 밖 경과음 수는 관찰 정보로 기록한다.
- 다음 과제: 70점 미만은 같은 목표에 밀도0.75, 이상은 다른 착지 목표/변주를 제안한다.

점수와 기록은 같은 세션의 practice_history에 함께 저장한다. 별도 전역 로그와 중복 저장하지 않는다.

## 8. AI 생성과 평가

order-2 조건부 백오프 Markov를 사용한다. JSON 학습 모델→부트스트랩→규칙 폴백 순서다.
스케일별 기본 리프와 `bake_progression`의 실제 진행 조건 예시를 함께 제공한다.
진행 생성은 선택 구간의 실제 코드·note_set·목표 착지·밀도·시드를 사용하며 음 길이를 코드 경계에서 자른다.
선택 밖 예시는 보존한다. 지원되지 않는 착지는 코드톤 예시로 대체하고 지원 여부를 메타데이터에 남긴다.

WJazzD 준비 데이터에는 solo/composition ID를 남긴다. 학습/검증은 composition 단위로 분리한다.
기존 15,512 프레이즈 모델의 원래 곡 분리는 입증할 수 없어 일반화 성능 수치를 붙이지 않는다.
평가용 재학습 모델은 cache에 따로 저장한다. 실제 모델/데이터 해시와 조건부 로그손실·생성 제약 검사를 보고한다.
세 모델의 제약 통과가 자연스러움/학습 효과의 우열을 뜻하지 않는다. 상세 수치는 AI_EVALUATION.md 참조.

## 9. MIDI·오디오

MIDI 0~15채널과 리프16/재청취17의 가상 재생 버스를 분리해 같은 음의 note-off 충돌을 막는다.
예약음은 재타건 세대 번호로 이전 타이머가 새 음을 끄지 않게 한다. 음량/키 해제/페달을 처리한다.
실제 피아노 소리를 사용하는 경우 내 연주 모니터 음량을0으로 둘 수 있다.

Qt FFmpeg 백엔드와 번들 ffmpeg atempo를 검증 기준으로 사용한다. 레거시 Windows WMF는 실제 seek 실패가 재현됐다.
근거: [Qt 백엔드 문서](https://doc.qt.io/qt-6/qtmultimedia-index.html#target-platform-and-backend-notes).
실제 장치 지연·장시간 청감은 자동 디코딩/시간축 검사와 별도다.

## 10. 현재 한계와 후속 검증

자동 코드의 장·단 3화음 어휘, 다운비트 위상·키·코드 오인식, 4/4 중심 학습 데이터,
스윙/altered 화성, 실제 MIDI 기기/장시간 청감과 사용자 학습 효과는 개선 관리 및 평가 문서에 기록한다.
실행 검증은 `python tools/run_checks.py`, 모델 평가와 음악 분석 평가의 재현 명령은 README에 있다.
